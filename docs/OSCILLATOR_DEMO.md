# Demonstrating PULSE periodic generation

Implementation language: Verilog HDL (Verilog-2001). Working contract: [OSC-CONTRACT-1](OSCILLATOR_CONTRACT.md). Actual results: [completion evidence](OSCILLATOR_COMPLETION.md).

## What to explain

PULSE accepts an external clock. Its one-shot timer produces one completion per accepted request; its periodic generator automatically repeats clock-enable events at a captured interval. Both and the debouncers use independent state. The demonstrated output is a registered tick, not a square-wave or physical oscillator.

At the illustrative 50 MHz input, P = 500,000 gives 100 events/second and P = 50,000,000 gives one event/second. Those are arithmetic examples, not claimed full-duration simulations. The recorded demonstration uses small counts so exact edges can be inspected quickly. Zero maps to one; P = 1 enables every cycle after startup and stays HIGH without gaps.

## Repeatable demonstration

Run in PowerShell from the repository root with ModelSim available:

```powershell
.\sim\run.ps1 -Test pulse_periodic_smoke_tb
.\sim\run.ps1 -Test pulse_periodic_checker_tb
.\sim\run.ps1 -Test pulse_periodic_tb
.\sim\run.ps1 -Test pulse_top_tb
.\sim\run.ps1
.\synth\run.ps1
```

The smoke bench gives a short startup/reload/reset trace. The checker-only bench detects nine deliberately incorrect samples and passes only if its expected outcomes agree. The real-module unit bench then requires zero checker errors. The top bench preserves P01-P07 and adds independent-operation cases P08-P11.

Use the final complete run's path printed by the runner to regenerate exported evidence:

```powershell
python docs/waveforms/extract_periodic_waveforms.py build/modelsim/run-<timestamp>
```

This uses Python's standard library for CSV/metadata extraction and Matplotlib for the PNGs when available. The HDL build itself needs neither Python nor Matplotlib. The helper expects the three periodic/unit/top VCD files generated by the full run; separate focused runs place them in different directories.

Open recorded WLF in ModelSim, then source `sim/wave.do` in the GUI Transcript using its repository path:

```powershell
vsim -view 'build/modelsim/run-<timestamp>/pulse_periodic_smoke_tb.wlf'
```

| Concurrency | Global disable at 2610 ns; reset at 2830 ns suppresses simultaneous expiries | Shared clear controls take priority and no stale event survives |

Show `src/pulse_periodic.v` and explain `active`, `captured_period`, and `remaining`. Then show that the checker uses elapsed-edge timestamps/modulo rather than the RTL downcounter. Finish by showing the seven PASS results and both synthesis reports, including the explained licensing warning.

## Demonstrate failure detection

This command is intentionally unsuccessful:

```powershell
.\sim\run.ps1 -Test pulse_periodic_tb -InjectFailure
```

It prints the deliberate failure and the runner reports simulator exit 4. It must not produce a success marker. Follow it with a normal focused run if demonstrating recovery. Do not label the injected run as a failed design regression or include its transcript among positive PASS evidence.

## Limits to state

Other-team interfaces remain provisional. Full maximum-period execution, physical oscillator behavior, duty-cycle square-wave generation, and FPGA timing closure are not demonstrated. The unchanged water-tank adapter disables periodic generation because its initial-response policy has no periodic consumer. A clocked event counter in the unit bench provides a concrete usage demonstration without inventing an external team requirement.
